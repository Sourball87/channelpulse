# Replit Prompt: Fix Reseller Detection (Filename + Fingerprint Mapping)

Fix the reseller detection pipeline in `parser.ts` and its use in `uploads.ts`. The current logic misattributes files: KS filename hints never fire on real filenames (spaces vs underscores), and because CA and KS share an identical header fingerprint, KS files can silently auto-commit as Computer Alliance. Do not refactor unrelated code.

## 1. Token-based filename matching (replace raw substring matching)

Replace `detectResellerFromFilename` internals:

- Build two representations of the filename (without extension):
  - `tokens`: lowercase, split on any run of non-alphanumeric characters (spaces, dashes, underscores, dots all behave identically). `2026 WK 28 Samsung SSD SOH reports - KS.xlsx` → `["2026","wk","28","samsung","ssd","soh","reports","ks"]`.
  - `collapsed`: lowercase with ALL non-alphanumerics removed → `2026wk28samsungssdsohreportsks`.
- Matching rules:
  - Short codes (≤ 3 chars, e.g. `ks`, `jw`, `ple`, `ca`) match ONLY as an exact token in `tokens`. Never substring-match short codes ("ks" must not match "weeks" or "stocks", "ca" must not match "cable").
  - Longer hints and DB `filename_patterns` are normalized the same way (strip non-alphanumerics) and matched against `collapsed`. So the hint `samsung_ssd_soh_reports_ks` becomes `samsungssdsohreportsks` and matches regardless of whether the file used spaces, dashes, or underscores.
  - Aliases: apply the same rule — ≤3 chars token-match, otherwise collapsed-match.
- Update the built-in hints: KS = token `ks` plus collapsed hints `samsungssdsohreports`, `samsungmonitorsohreports`, `samsungmobilitysohreports` (each implies KS only when the `ks` token is also present OR no other reseller token is present — see ambiguity rule below). Remove the generic `samsung_soh_report` hint from Computer Alliance entirely: it is too generic and collides with KS naming. CA keeps `computeralliance` (collapsed) and token `ca`.
- If tokens/hints match MORE THAN ONE reseller, return ambiguous: `{ resellerId: null, candidates: [...], confidence: 0 }` and force review with the candidates pre-listed.

## 2. Separate "format" from "reseller" in header fingerprints

Header fingerprints identify a report FORMAT, and some formats are shared by multiple resellers (CA and KS use the same layout; the V-Report layout is used by several). Restructure:

- Define formats once: `{ formatId: "ca_ks_weekly", headers: [...], resellers: ["ca","ks"] }`, `{ formatId: "v_report", headers: [...], resellers: ["pccg","jw","digi", ...whoever uses it] }`, plus the single-reseller formats (scorptec, ple, umart, centrecom_legacy).
- `detectResellerFromHeaders` returns the matched format and:
  - If the format maps to exactly one reseller → that reseller with confidence = similarity.
  - If the format maps to multiple resellers → try tie-breakers in order: (a) sheet-name rules (existing ComputerAlliance / Samsung SOH report / ItemForcastReport / Forecast checks), (b) filename token result if it matched one of the format's resellers, (c) learned associations (see §4). If no tie-breaker resolves it, return `{ resellerId: null, formatId, candidates: [the format's resellers], confidence: 0 }`.
- Remove the strict-greater DB-order tiebreak (`sim > bestMatch.confidence` letting the first reseller win). Ambiguity must surface, never be resolved by row order.
- V-Report special case: delete the `sim * 0.6` pseudo-confidence. An unresolved shared format contributes 0 to reseller confidence. Keep the format detection so the review card can say "V-Report format detected — used by PCCG, JW, DigiDirect" with those candidates as quick-pick buttons.

## 3. Auto-commit gate hardening

In `uploads.ts`, auto-commit is allowed only when ALL of:
- reseller resolved to exactly one candidate,
- detection agreement: filename token/hint AND (header format OR sheet name) point to the same reseller — OR the header format is unique to that reseller,
- overall confidence ≥ 0.9, week detected from filename, no overwrite conflict (existing rules).

If reseller was resolved by a multi-reseller format's tie-breaker other than filename+sheet agreement, always queue for review (status "review") even at high confidence. Show the resolution reasoning on the review card: "Detected KS via: filename token 'ks' + CA/KS format match".

## 4. Learn from manual corrections

When a user assigns or corrects a reseller in the review screen and commits:
- Save the collapsed filename with the volatile parts stripped (remove pure-number tokens and detected date/week tokens) as a new entry in that reseller's `filename_patterns`, e.g. `samsungssdsohreportsks`. Dedupe.
- Save the header fingerprint (sorted normalized headers, joined) into a new `reseller_format_associations(reseller_id, fingerprint, created_at)` table. On future files, if a shared-format file's fingerprint + one distinctive filename token matches a learned association, resolve to that reseller at 0.85 confidence (still subject to the §3 auto-commit gate).
- Show a toast: "Got it — files like this will be recognised as KS from now on."

## 5. Regression tests

Add unit tests for `detectResellerFromFilename` and `detectResellerFromHeaders` covering at minimum:
- `2026 WK 28 Samsung SSD SOH reports - KS.xlsx` (spaces + dash) → KS
- `2026_WK_28_Samsung_Monitor_SOH_reports_-_KS.xlsx` (underscores) → KS
- `samsung_soh_report.xlsx` with sheet "ComputerAlliance" → CA; same filename with sheet "Samsung SOH report" → KS; same filename with sheet "Sheet1" → ambiguous, candidates [CA, KS], no auto-commit

- V-Report headers with unhelpful filename → resellerId null, candidates listed, overall confidence below auto-commit, status "review"
- Scorptec/PLE/Umart/Centrecom formats still resolve as before (no regressions)
