# Replit Prompt: ChannelPulse Bug Fixes & Improvements (Code Review Round 1)

Fix the following issues in priority order. Do not refactor unrelated code.

## P0 — Data loss: multi-file resellers wipe each other

KS uploads 3 files per week (SSD, Monitor, Mobility) for the same reseller+week. Current behavior destroys data:
1. `commitUploadInternal` with `confirmOverwrite=true` deletes ALL `inventory_snapshots` for the reseller+week, then inserts only the new file's rows. Committing KS's Monitor file deletes the SSD snapshots.
2. `upload.tsx` hardcodes `confirm_overwrite: true` on every commit, so the 409 protection never fires.

Fix:
- Scope the overwrite delete to only the part_ids present in the incoming file: `DELETE FROM inventory_snapshots WHERE reseller_id = ? AND week_iso = ? AND part_id IN (incoming parts)`. Then insert. Different-part files for the same reseller+week must coexist.
- Change the insert to a proper upsert on (reseller_id, part_id, week_iso) with DO UPDATE, replacing `onConflictDoNothing` (which silently drops corrected re-uploads).
- Frontend: remove the hardcoded `confirm_overwrite: true`. On a 409, show a dialog listing how many snapshots for which parts will be replaced, with Confirm/Cancel. Only send `confirm_overwrite: true` after explicit confirmation.
- The "overwrites existing" pre-check in POST /uploads should compare at part level too, so KS file #2 with different parts is NOT flagged as an overwrite.

## P0 — Review screen must allow correction

In `upload.tsx`, `handleCommitReview` blocks commit when `detected_reseller_id` is null and offers no way to fix it. Add to each review card:
- A reseller dropdown (all active resellers) pre-filled with the detection, editable.
- A week selector pre-filled with the detected week, editable.
- On commit, send the user's chosen values. On the server, `commitUploadInternal` must also update `uploads.reseller_id` and `uploads.week_iso` to the committed values (currently only status is updated, which breaks reporting-compliance and duplicate checks).
- When the user corrects the reseller, offer "Remember this filename pattern for [reseller]" which appends a distinctive filename token to `resellers.filename_patterns`.

## P1 — Week handling

- When no week is detected from the filename, do NOT default to the current week and never auto-commit. Force review with the default set to the most recent completed ISO week (previous Mon–Sun), clearly labeled "week not detected — please confirm".
- Replace all uses of `previousWeekIso` (string arithmetic, breaks on 53-week ISO years like 2026 and on data gaps) with "the most recent week strictly before X that exists in inventory_snapshots". Create one shared helper and use it in dashboard, explorer, health, and reseller-performance.
- Remove the dead conditional `confidence >= 0.9 ? "review" : "review"` in uploads.ts.
- Fix same-batch duplicate detection: track file hashes seen within the current upload request so two identical files in one batch produce one upload + one duplicate card.
- Auto-commit gate: if reseller detection came only from a generic filename hint (e.g. "samsung_soh_report"), require the header fingerprint to also match that reseller before auto-committing; otherwise queue for review.

## P1 — One shared WOI definition

Create a single utility used by dashboard heatmap, explorer, alerts, and all insight routes: WOI = SOH ÷ (trailing 4-week avg ST, excluding annotated bulk-deal weeks), falling back to current-week ST if no history. Today three different definitions exist (dashboard uses current ST, rebalancing uses trailing-first, overstock uses current-first), so the same cell can be green on the heatmap and overstocked on insights.

## P1 — Implement the bulk-deal exclusion for real

`insight_annotations` marked as confirmed bulk deals must actually be excluded from every trailing-average calculation (stockout risk, rebalancing, overstock, spike detection baseline, and the shared WOI helper). Add an annotation type "bulk_deal" set from the anomaly card's confirm action. Currently the UI promises exclusion but no endpoint filters annotated weeks.

## P1 — Active stockout detection for vanished SKUs

Most resellers omit out-of-stock SKUs from their files entirely. In insights-stockout, also detect: reseller×part combos with trailing avg ST > 0 in the prior 4 weeks that have NO row (or SOH=0) in the current week, provided the reseller reported this week. These are the biggest lost-sales cases and are currently invisible.

## P2 — Insight quality fixes

- **Whitespace/breadth**: only evaluate resellers that have committed data for the selected week; for non-reporters, either exclude them or use their most recent prior week, labeled "as of Wxx". Stops false "range gap" floods when uploads are pending.
- **Concentration risk**: only flag SKUs with channel ST ≥ 10 units for the week (make threshold a setting). One reseller selling the only 1 unit is not a risk signal.
- **New line adoption**: only treat a part as "new" if its first_week is strictly after the earliest week in the database AND the database has more than 8 weeks of history; otherwise skip the section with a "needs more history" placeholder.
- **Rebalancing**: require starved reseller trailing_avg_st > 0 (remove the donor-ST-halved heuristic for zero-history resellers); decrement each donor's spare capacity as opportunities are generated so a donor is never over-committed across multiple suggestions; align insufficient_data to `< 2` weeks like the other endpoints.
- **Anomalies**: move the negative-SOH check outside the `prev4Weeks.length > 0` block so it works from week 1.
- **Parser**: remove "sapcode" from the part_no synonym list (it is Umart's internal numeric code, not a part number). Enforce max one source column per canonical field: keep the highest-confidence match, mark others unmapped, and show a warning chip in the mapping review when a collision occurred.
- **Parser robustness**: if the first row doesn't map to at least a part_no column, scan the first 10 rows for the real header row (some resellers add title rows).
- Remove the unused `getSavedMappings` function in uploads.ts.

## P2 — Expected files per reseller

`resellers.expected_weekly_files` exists but is unused. Dashboard reseller status and the missing-upload alert should show "KS: 1 of 3 files received" and treat < expected as not fully reported. Count committed uploads per reseller per week.

Include a print stylesheet so browser print-to-PDF looks clean. No new data entry, reuse the existing insight endpoints server-side.
